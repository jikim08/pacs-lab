# 프로젝트 기획서

> 상태: 검토용 초안 · 개정일: 2026-11-16
> 기준: Term Project 안내문 및 [최신 기능 명세서](functional-specification.md). 구현 완료나 팀 정책 확정을 의미하지 않는다.

## 1. 목적과 대상

공개 영상과 모의 환자·케이스를 사용해 의료영상의 등록, 열람, 처리, 검토 및 업무 현황을 연결하는 교육용 웹 PACS 프로토타입을 개발한다. 대상은 영상 등록·처리·검토 업무를 수행하는 모의 사용자다. 서비스 이름, 구체적인 사용자 문제와 특화 기능은 미결정이다. 실제 환자정보와 비공개 병원 자료는 사용하지 않고, 결과를 진단이나 임상 성능의 근거로 표현하지 않는다.

## 2. 범위와 성공 기준

| 범위 | 목표와 완료 근거 |
|---|---|
| 사용자·권한 | Firebase 인증, 역할별 기능 및 데이터 접근 검사. 허용·거부 요청 검증. |
| 케이스·영상 관리 | 등록·검색·필터·수정·배정 및 영상 저장·재조회. 삭제/보관은 정책 결정 후 적용. |
| 뷰어·분석 | 확대·축소·이동·초기화, 원본/결과 비교, ROI 통계와 히스토그램. |
| 영상처리 | 명암 개선·노이즈 제거·경계 검출 영역에서 서로 다른 알고리즘 3종 이상, 설정 조절·결과 저장·이력 조회. 실제 방법은 미결정. |
| 검토·현황 | 대기·담당 목록, 메모·리포트·완료·재검토, 상태별·담당자별 현황 및 기록 조회. |
| 특화 기능 | 공통 기능 외 1개 이상을 선정·구현하고 같은 모의 업무로 개선점과 한계를 검증. |
| 제출·재현 | 배포 주소에서 핵심 흐름 수행, 재시작 후 재조회, 실행 안내와 개인별 기여 근거 확보. |

최신 기능 명세는 7개 영역·54개 기능이다. 이는 목표 범위이며 현재 DB가 모든 기능을 지원한다는 뜻은 아니다. 특화 기능은 아직 선정되지 않았으므로 54개 중 어느 기능을 특화 기능으로 인정할지도 별도 검토한다.

## 3. 기술과 데이터 기준

안내문은 Python·Streamlit, Firebase Authentication, Cloud Firestore, JCloud 및 Git/GitHub를 지정한다. 영상 파일은 Firebase Storage 또는 JCloud 영구 저장 공간에 두고 업무 DB에는 위치를 기록한다.

최신 기능 명세는 8개 논리 테이블과 PostgreSQL 언급을 포함한다. **안내문의 Firestore 지정과 DB 변경의 허용 여부를 확인해야 한다.** 승인 전 PostgreSQL 채택이 확정된 것으로 취급하지 않는다. 8개 구조는 논리 데이터 모델로 사용하고 물리 구현은 [설계서](04_Architecture_Data.md)에서 구분한다.

공개 데이터 출처·이용 조건을 기록한다. DICOM·장비 연동, 파일 형식·크기, 알고리즘과 특화 기능은 미결정이다. ROI·히스토그램은 최신 명세상 영구 저장 요구가 없지만 처리 파라미터의 이력 조회에는 저장 구조 추가가 필요하다.

## 4. 작업 계획과 역할

팀은 3~4명이며 이름·학번·GitHub 계정·담당 기능·담당 알고리즘·완료 조건을 합의해야 한다. 모든 팀원이 직접 코드 구현·검증 및 동료 리뷰에 참여한다. 담당자와 중간 날짜는 미결정이며 아래는 작업 순서 제안이다.

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 범위·권한·상태·특화 기능·DB 결정 | 미결정 목록에 결정 내용과 근거 기록 |
| 2 | 화면·데이터·저장·오류 처리 설계 | 요구사항과 데이터 지원 여부 연결 |
| 3 | 인증→등록→열람→처리→검토 흐름 구현 | Issue·PR·리뷰 및 정상 흐름 검증 |
| 4 | 예외·권한·동시 변경·저장 복구 검증 | 예상/실제 결과와 결함 기록 |
| 5 | JCloud 배포·보고서·시연 | 외부 접속과 실행 재현, 제출물 점검 |

## 5. 위험과 대응

| 위험 | 대응 |
|---|---|
| DB 선택의 과제 조건 불일치 | Firestore 지정과 최신 DB 논의를 확인하고 물리 설계를 확정한다. |
| 8개 구조의 데이터 부족 | 파라미터·리포트·변경 이력 등 부족분을 합의 후 추가한다. |
| 범위·특화 기능 미확정 | 사용자 불편과 비교할 모의 업무를 먼저 결정한다. |
| 파일/DB 부분 저장 실패 | 성공 판정과 복구 절차를 분리하고 실패를 검증한다. |
| 기여 근거 또는 일정 누락 | 기능별 Issue·담당자·완료 기준과 PR·리뷰·검증 결과를 남긴다. |

## 6. 제출

마감은 **2026년 12월 18일 23:59 한국 시간**이다. GitHub 저장소, JCloud 접속 정보, 보고서 PDF, 팀 전체 3~5분 시연 영상을 제출한다. 최종 커밋과 배포 버전을 맞추고 채점 기간 서비스를 유지한다. 팀원 모두 LMS에 이름·학번·전체 팀원 정보, 저장소 URL·커밋 SHA, 접속·로그인 정보와 영상 링크를 적고 같은 보고서를 첨부한다. 비밀번호·서비스 계정 비밀키는 저장소에 넣지 않는다.
